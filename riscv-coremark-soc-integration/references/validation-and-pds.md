# 验证、成绩和 PDS 交接

在需要给出 CoreMark 成绩、安排回归仿真或导入 PDS 时使用本页。将工程中的实际顶层名、端口、地址图和工具路径写进项目 README 或运行脚本，而不是写死到技能本身。

## 建议保存的集成记录

| 项目 | 应记录的内容 |
| --- | --- |
| CPU 数据接口 | 读时序、地址/数据宽度、写使能、字节使能、复位行为 |
| 地址图 | 每个 D-Mem/MMIO 窗口、寄存器偏移、读写权限和未映射访问结果 |
| UART | 帧格式、波特率、TX 忙/ RX 有效/溢出位，以及读取 RX 后的行为 |
| 镜像 | 构建命令、ISA/ABI、字节序、I-Mem/D-Mem 深度、镜像路径和容量检查结果 |
| 性能运行 | CoreMark 运行模式、数据规模、迭代数、时钟频率、计时周期和 UART 结论 |

## 验收顺序

在完整 CoreMark 前，先让定向测试分别证明：

1. D-Mem 在其窗口正确读写，且相邻 MMIO 窗口不会响应。
2. GPIO 写入和输入读取的寄存器选择正确。
3. Timer 低/高位读出稳定，软件对开始和结束标志的写入可观察。
4. UART TX 寄存器写入产生正确帧，忙位阻止或定义连续写入行为。
5. UART RX 接收一个字节后置有效位，软件读取后按约定清除有效位；测试溢出行为（若设计提供）。

完整运行的 testbench 应设定可诊断的完成条件和超时条件。至少记录：程序完成事件、超时与否、Timer 周期值、UART 观察到的验证文本、UART 帧错误计数和最后的 PC/关键寄存器状态。若软件用 MMIO 写入开始/结束标志，监视该状态转换通常比猜测某个 PC 地址可靠。

## CoreMark 结果判定

将一次性能成绩标记为有效前，确认：

- 目标 ISA 与硬件实现相符，例如无乘除法硬件时为 RV32I。
- 代码和数据镜像均未超出 I-Mem/D-Mem 容量，且 `.rodata` 从 CPU 可访问的数据地址读取。
- 仿真没有超时，程序完成路径已被 testbench 观察到。
- UART 输出包含 CoreMark 的验证成功文本，而非仅有启动横幅。
- 使用 Timer 周期数计算成绩，`iterations / (cycles / 1_000_000)`；用于对外比较的性能运行持续至少 10 秒，并记录采用的硬件时钟频率。

短数据规模、低迭代次数和缩短运行时间适合快速定位问题，但应标为冒烟结果，不能与正式 2 KiB 性能结果混写。

RTL 仿真可证明功能、周期数和软件输出，不能证明后布局布线 Fmax、LUT/BRAM 利用率或实板结果。除非用户明确要求上板验证，停止在仿真和实现工具报告的范围内，并说明该边界。

## PDS 交接

将综合 SoC 顶层设为项目顶层，并在一次编译集中只加入每个 RTL 模块的一份。常见问题是同时加入源目录、导出 Verilog 目录或 UART 的多个变体，导致模块重复定义或意外采用旧版本。

确保 `imem.hex` 和 `dmem.hex` 可从实现运行目录读取，或通过顶层参数传入已验证路径。运行 PDS 前复查顶层参数的存储器深度与镜像构建参数一致。

在作出频率结论前，为 CPU 时钟提供 `create_clock` 或工具等价的时钟约束。综合、Device Map 和 Place & Route 通过只说明实现流程完成；时序结论应以实现后的 timing report 为准。
