# RISC-V CoreMark SoC Integration

将现有 CPU、外设和 CoreMark 软件连接成可综合、可复现实验的 SoC。先理解现有 RTL 的真实接口和时序，再增加最小的适配层；不要因为本技能而替换 CPU 微架构、地址映射或用户选定的 UART 实现。

## 先确认 CPU 合约

在改 RTL 前，从 CPU 顶层、执行级和原 D-Mem 路径确认以下事实：

- 读数据是在同一周期组合返回，还是在下一周期返回；外设读路径必须满足该时序。
- 读写地址、写使能、数据宽度、字节使能、对齐方式和复位极性。
- CPU 采用 Harvard 还是统一存储器，以及代码、`.rodata`、已初始化数据各自可访问的地址空间。
- 实现的 ISA。没有 RV32M 时，CoreMark 必须以 `rv32i` 构建；不要保留综合工具无法映射的乘除法硬件作为未使用逻辑。

如果现有执行级依赖组合读，不要在总线或 GPIO/Timer 适配层引入同步寄存器读。对不支持的访存或 ALU 编码，相关组合输出仍须有默认赋值，避免锁存器或 X 状态掩盖问题。

## 集成总线和外设

为一个主设备建立明确的 MMIO 互连，并将地址图记录在工程文档中。地址图应由当前工程决定，不能把示例地址照搬到其他 CPU。

- 分别对读地址和写地址译码，分别产生各从设备的 `cs`、`re`、`we` 和寄存器选择；未映射读返回确定值。
- D-Mem 负责普通 load/store，外设只在自己的窗口响应。检查读/写是否同时访问相同窗口，以及写数据不会泄漏给其他从设备。
- 将独立 UART 包装成寄存器接口，至少定义 TX 数据写、状态读和 RX 数据读。状态应能表示发送忙、接收有效，必要时表示溢出；读取 RX 数据的清除语义要与软件驱动一致。
- UART 包装层的位宽、波特率、帧格式和 FIFO/缓冲参数必须与被复用的 UART 模块实际端口匹配。先为寄存器路径写定向测试，再依赖 CoreMark 输出判断。
- GPIO 和 Timer 采用与 CPU 读时序一致的实现。计时器应提供软件可读取的周期值，并清楚定义开始、结束或中断标志的写入语义。

## 准备存储器和 CoreMark 镜像

为 `$readmemh` 生成与 RTL 宽度、字节序和深度匹配的镜像。Harvard CPU 通常需要独立的 `imem.hex` 和 `dmem.hex`；数据镜像必须含 `.rodata` 和所有经数据总线访问的初始化对象。生成后先检查每个镜像的最大地址和容量，不能静默截断。

初始化 RAM 时，先给全部单元确定值，再调用 `$readmemh`。若 PDS 在 4096 字初始化循环上出现展开或映射问题，将该深度拆成四个连续的 1024 次循环，并保持 `$readmemh` 在四段清零之后；其他深度仍可使用常规参数化循环。

使 CoreMark 编译参数与硬件一致：ISA、ABI、数据大小、迭代次数、D-Mem 基址和 `CPU_FREQ_HZ` 都应记录下来。用于可比较成绩的性能运行通常采用 2 KiB 数据规模和足够长的实测时间；短运行只作为冒烟测试。

## 分层验证

按下面顺序推进，并在失败时停留在最小能复现问题的一层：

1. 编译完整综合顶层，确认所有 RTL 只有一份且顶层、参数和 include 路径正确。
2. 使用小型 testbench 覆盖 D-Mem 读写、GPIO、Timer 读数、UART TX；另测 UART RX 的有效位和读取清除路径。
3. 使用少量迭代的 CoreMark 镜像确认复位、程序启动、结束标志和 UART 文本路径。
4. 再运行完整 CoreMark，要求程序完成、UART 出现验证成功文本、计时器给出非零周期数，并满足该成绩声明所需的运行时长。

从硬件计时器的周期数计算 `CoreMark/MHz = iterations / (cycles / 1_000_000)`。不要用仿真器墙钟时间替代 CPU 周期；若需报告指定时钟下的 CoreMark 总分，再乘以该时钟的 MHz。

在设计验证、成绩报告或 PDS 交接时，读取 [references/validation-and-pds.md](references/validation-and-pds.md)。它定义了结果有效条件、PDS 文件组织和应记录的证据。
