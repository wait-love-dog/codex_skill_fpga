# ACX720-010：粘滞按键事件在清除前被反复执行

- 日期/状态：2026-11-06，软件语义缺陷已修复并通过生产 C 回归；物理 S1 逐次按下尚未专门验收。
- 环境：F11/F12 板机协同固件，S0～S3 低有效，经硬件消抖后事件保持到 W1C。
- 现象：初版主循环每次读到 S1 事件就取反静音，但事件为了送到电脑而保持到下一次帧头发送。其间主循环可执行多次，静音状态会反复翻转。
- 根因：把“保持的待消费事件”误当成“本周期新发生的脉冲”。按键去抖无法修复消费者重复消费。
- 修复：软件跟踪已处理事件位，只执行新事件；帧头携带事件后 W1C，清除后才允许下一次事件。电脑静音命令采用绝对状态而非取反，避免重复包再次改变状态。
- 验证：直接执行真实生产 C 的 MMIO 适配测试：同一事件保持多次调用只翻转一次，清除再发生才翻转；同时覆盖串口静音、确认和失联。该测试不替代按键电气和实际听感。
- 证据：`fall_detection/evidence/firmware_native.json`、`tools/test_firmware.py`，旧逻辑快照 `evidence/key_event_before.c`。
- 复用：每个事件明确“产生、保持、消费、清除”的所有者；状态命令和边沿命令应分开。
