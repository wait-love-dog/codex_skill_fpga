# ACX720-003：新增状态寄存器读到旧 CTRL，程序等待状态而静默

## 来源与状态

2026-10-31 D5 历史记录报告该问题已修；2026-11-01 对实际源文件、可运行 D5 串口及新生产顶层做回归。历史失败现场来自原工程记录，不声称本轮重新捕获过旧失败位流。

## 根因与现象

视频 MMIO 原只覆盖 0x00～0x3C，CPU 用 `data_addr[5:2]` 输出 4 位索引。新增 `0x40 DBG_LOCK` 后仍沿用旧位宽，地址别名成 0x00 CTRL，锁定判断一直为 0；旧软件等锁定后才输出，因此表现为 LED 变化而串口不发数据。

只修改 CPU 侧宽度还不够：从设备写逻辑若仍 `case(reg_idx[3:0])`，新增 0x48 命令也会被解释为旧 0x08 FB_DATA。新增独立控制逻辑可能同时运行，使这种别名更隐蔽。

## 修复与回归

- CPU 输出 `data_addr[7:2]`，端口保持 6 位；从设备读写均使用完整 `reg_idx`。
- 状态等待期间仍提供心跳或显式错误；“串口静默”不能兼任所有等待与失败状态。
- 本轮顶层仿真用真实生产连接，对高地址版本号、命令、状态、曝光读回和旧 CTRL 做比较，覆盖自动/锁定及跨域快照。
- 原 D5 重新下载后串口持续输出，60 秒 1805 帧全部 n=32000。该板上结果证明当前版本可运行，不代替旧故障复现。

工程内依据：`video/D5_硬件采集步骤.md` 的历史故障记录、`video/rtl/cpu/pulpino_soc.v`、`video/rtl/video_ctrl.v`、`video/evidence/d5_control_20261101/`。

下次扩展 MMIO 时同时核对 CPU 截位、端口宽度、从设备读译码和写译码；用新旧地址对照检查别名，不能只测试新寄存器能否读出一个非零值。


## D7 地址扩展回归（2026-11-02）

新 UI 使用 0x80～0xB4，继续保留 6 位地址索引。生产顶层按索引最高位分发到原控制器与 UI 控制器；由于两者都为一周期寄存器读，读回选择也要延迟一周期，不能直接用当前地址选择上一拍数据。

真实生产顶层 XSIM 已检查 UI 版本、旧版本交替读回、UI 写不改变旧 CTRL/帧缓存写，以及 0xC0 不别名到 0x80。实板自动操作取得 165 条显示端已应答记录，用户确认界面、画面和绿框正常。依据为 `video/evidence/d7_ui_20261102/` 的 sim_top、board_verification 和 user_feedback。此轮为旧故障预防回归，没有重新发生旧地址截断故障。
