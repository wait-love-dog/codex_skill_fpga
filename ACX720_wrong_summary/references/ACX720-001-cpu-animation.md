# ACX720-001：CPU 背景出现，白色进度条不动

## 状态和范围

已解决，2026-10-31 用户确认白色进度条正常循环增长、清空。
平台为 ACX720-V3、xc7a100tfgg484-2、Vivado 2019.1；本视频 SoC 的 CPU 为 80 MHz。
这不是整板固定的软件、频率或开关功能。

## 现象

屏幕有渐变背景但没有白色进度条动画，LED 不亮；拨动 SW0 时才有反应。旧帧缓存仍保留图像，容易误判为 CPU 在运行、仅绘图算法有问题。

## 两层实际错误

1. 顶层 `rst_cpu = rst_p | ~locked_cpu` 为高有效复位请求，却接到 CPU 和 `video_ctrl` 的 `rst_n`。模块内部均为 `if (!rst_n)`。正常工作时请求降为 0，反而持续复位。
2. 修正端口极性后，默认拨码高电平仍被当成复位有效。实板 ILA 测得三个原始开关输入为 `111`、PLL 已锁定，但 CPU/显示运行信号仍为 0、PC 为 0、帧缓存无写入。

因此“修正 rst_n”只是第一步，未通过最终验收；还须修正物理拨码到逻辑控制的映射。

## 为什么先前测试漏掉

早先 testbench 只实例化 CPU，并直接给正确的低有效复位，视频读回被常量替代。它没有覆盖生产顶层的复位组合、默认开关电平和真实视频从设备，无法证明板上集成正确。

## 修复与有效测量

- 高有效请求转为正确的低有效复位；CPU 与显示时钟域分别同步释放，按各模块实际接口连接。
- 该工程约定 SW0 原始电平 1 运行、0 复位；SW1 电平 1 显示帧缓存、0 显示硬件彩条。用电平描述，不只用 ON/OFF 或拨动方向。
- 检查 POR、LOCKED、run、PC、LED 寄存器及帧缓存写使能，再检查白色像素的数据与地址。
- 只对复位同步器明确的异步控制引脚设置有依据的时序例外；不能宽泛切掉同步链数据路径及下游时序检查。

## 验证与验收

- 生产顶层 XSIM 使用真实 CPU、镜像、视频控制器、帧缓存和厂商时钟模型；仅缩短 POR 等待，覆盖默认 `111`、手动复位及释放。
- 完整绘图回归比较 307200 个帧缓存像素，并检查显示输出确实出现动画白像素。
- 实板修复后相同 `111` 输入下 run=1、PC 执行、LED 寄存器变化；四次 ILA 触发共记录 760 次白色像素写入，地址位于动画的 200～231 行。
- 最终开关修复版本布线后 WNS +0.884 ns、WHS +0.054 ns，DRC 无 error/critical warning。此前仅复位修复版本的时序数值不同，不能混用。
- 用户可见动画验收通过。使用 JTAG 下载，未写配置 Flash。

## 下次可复用的判断

“按复位时才运行”优先检查复位极性和物理开关电平。优先补生产顶层的失败复现，而不是继续改绘图延时、白色数值或 CPU 算法。开关极性、控制含义和复位端口有效电平是三个分别核对的事实。
