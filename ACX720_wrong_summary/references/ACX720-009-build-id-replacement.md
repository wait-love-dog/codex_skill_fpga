# ACX720-009：生成脚本把十六进制版本标识改成标签文字

- 日期/状态：2026-11-06，构建层已修复，最终下载版本已读回 AC720F12。
- 环境：Vivado 2019.1，D7 构建包装器迁移到跌倒协同工程。
- 现象：综合布线完成，最终 bitgen 报 USR_ACCESS 非法。原脚本先把全文 D7 改为 FALL，连 AC720D71 也变成 AC720FALL1；后续针对旧完整标识的替换已匹配不到。
- 根因：无边界文本替换同时修改了人类阶段标签与机器常量。失败发生在位流生成，不能归因于 RTL、资源或时序。
- 修复：先替换明确的 32 位标识，再改人类标签；构建前检查预期常量。对已有成功布线结果重新设合法标识并生成位流，保留原错误日志；未降低 DRC 或时序门槛。
- 验证：重新生成通过；后续 F12 从完整构建通过 WNS/WHS 和 bitgen，JTAG 读回 AC720F12、DONE=1、CRC_ERROR=0。
- 证据：`fall_detection/evidence/f11_before/build.log`、`finish.log`、最终 `build.log` 和 `program.log`，以及 `tools/build_fpga.py`。
- 复用：构建 ID 应由独立常量/占位符管理，生成前校验 8 位十六进制；不要为纯标签错误重复修改布局策略。
